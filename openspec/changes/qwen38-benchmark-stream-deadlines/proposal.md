# Per-Token Deadlines, Stream-Stall Checks, and Prefill-Interference Mode for `qwen38-benchmark`

## Why

The imported `qwen38-benchmark` runner (`onix.qwen38-benchmark.v1` / `onix.qwen38-agentic-benchmark.v1`) only reports TTFT and per-call mean ITL (`(last_token - ttft) / (completion_tokens - 1)`). A stream that stalls mid-generation and then emits a trailing burst can exhibit identical TTFT and identical mean ITL to a smooth stream while failing real user-perceived interactivity deadlines. Furthermore, throwing exceptions on failed/truncated streams or silently excluding unobservable samples hides tail failures from the evaluation population.

Tracking `OnixResearch/tt-onix#17` inside `OnixResearch/inference-lab` extends the portable standard-library Python benchmark with bounded per-event streaming observations, strict chunk-vs-token separation, versioned gap and cumulative-token-deadline semantics, full population failure retention, and a reproducible prefill-interference benchmark mode without breaking legacy `v1` schemas or altering the frozen donor fixtures (`corpus.json`, `agentic_trace.json`).

## Change

1. **Bounded streaming observations**: Capture monotonic client-side arrival offsets for content-bearing SSE events separately from heartbeat comments, role-only deltas, usage-only chunks, empty chunks, and `[DONE]` markers under an explicit per-stream event bound (`--max-trace-events`, default `4096`). Record overflow explicitly (`trace_truncated`, `overflow`, `dropped_trace_events`) and invalidate gap/deadline compliance on overflow or invalid timing. Store incremental content hashes and character counts rather than raw response text or credentials.
2. **Strict chunk-vs-token separation**: Always label client-observed content-event gaps explicitly (`content_event_gaps`, `event_gap_seconds_*`) and distinguish client SSE delivery time from device generation time. Evaluate cumulative per-token deadlines (`TTFT_SLO + (i - 1) * TBT_SLO`) only when an explicit, verified token-to-event mapping is present (`endpoint_token_ids` or `endpoint_cumulative_tokens`); report `token_deadline_compliance` explicitly as `unavailable` (never `passed` or `0`) when no explicit mapping exists. Never fabricate token timestamps by spreading multi-token chunks or equating one SSE delta with one token.
3. **Versioned additive metric semantics**: Preserve all legacy `onix.qwen38-benchmark.v1` and `onix.qwen38-agentic-benchmark.v1` fields, workload digests, and `run`/`agentic`/`compare` compatibility. Add versioned stream-deadline observations (`onix.qwen38-stream-deadlines.v1`) reporting within-stream content-event-gap `p50`/`p95`/`p99`/`max`, per-request max-gap distributions, explicit `event_weighted` vs `request_weighted` aggregations with sample counts, and strictly distinct `max_gap_within_budget` vs `every_token_meets_deadline` verdicts.
4. **Full failure retention in the evaluation population**: Track mutually exclusive `completed`, `rejected`, `timed_out`, `incomplete` (including `cancelled`), and `unobservable` counts summing to `offered` alongside `admitted` (`unknown` when endpoint-only), failure/unknown rates, goodput, arrival mode (`closed_loop` vs `interference_burst`), duration, offered load, warmup, SLO denominators, and fail-closed `run_status`.
5. **Reproducible prefill-interference fixture and mode**: Keep `agentic_trace.json` and `corpus.json` byte-identical to `tt-onix@5ed5e90c`. Add frozen `pkgs/qwen38-benchmark/prefill_interference.json` and an `interference` subcommand (`onix.qwen38-prefill-interference.v1`) comparing bounded long-lived victim streams under a deterministic long-prompt prefill burst against a matched short-prompt or idle control on the same endpoint, marking server-side phase attribution as `unavailable`.
6. **Device-free tests and provenance updates**: Expand `--self-test` with deterministic pure timestamp-reducer tests (including the exact `#17` smooth-vs-burst witness and cumulative-deadline slack test) and injected-clock loopback SSE tests covering all positive and negative streaming cases. Update `PROVENANCE.json`, `pkgs/qwen38-benchmark/default.nix`, `docs/qwen38-benchmark.md`, and `tests/qwen38_benchmark_import.rs` while keeping `evidence/` byte-identical.

## Scope and limitations

- Client-only standard-library Python observations: timestamps reflect client SSE delivery time, not accelerator kernel generation time, and cannot attribute server-side prefill vs decode scheduling phases.
- No live model endpoint, accelerator driver, hardware telemetry, or production serving cutover is claimed.
- Existing Rust core (`src/serving_bench.rs`) and retained `evidence/batch1/`–`evidence/batch6/` bundles remain byte-identical.
