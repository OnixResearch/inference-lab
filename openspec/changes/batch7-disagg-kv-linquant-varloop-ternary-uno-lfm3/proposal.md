# Batch 7: Disaggregated KV transfer, 2-Spark RDMA TP & KV checkpointing, CopyDrafter, Hypertune KV adapters, Qwen3.8 Longbook GDN, LinQuant recurrent rewrite, TML varloop + 2DSD protocol, ttf-home ternary Qwen3.8, Draft-OPD/D-PACE replay, K2 Uno/MoVA, and LFM3/d1 typed decisions

## Why

Batches 1–6 established `OnixResearch/inference-lab` with a deterministic, dependency-free pure-Rust core (`unsafe_code = "forbid"`), offline Nix tooling (Rust 1.85.1), and bounded contract harnesses covering issues `#1`–`#61`. Batch 7 implements the next twelve tracked issues (`#62`–`#73`), all strictly default-off:

- `#62` (`disagg-kv-transfer`): Bounded default-off contract and wire format for disaggregated Spark-CUDA prefill to Apple-Metal decode prefix-cache transfer over 10GbE vs single-host prefill+decode, verifying exact token/logit parity on frozen prompts and separating wire bytes/token and cold/warm TTFT (`#5`, `#42`).
- `#63` (`spark-rdma-tp`): Related-work pin for RLX (`post_only_unlocated_paper_repo`) and bounded 2-node DGX Spark raw-RDMA tensor parallelism with 4-bit attention vs replicated and layer-split baselines at `8K`, `128K`, and `1M` context, gating throughput strictly behind numerical and long-context task parity (`#8`).
- `#64` (`spark-kv-checkpoint`): Default-off profile pinning `MiaAI-Lab/GLM-5.3-Flash-DGX-Sparks-1104@6c55c20da31a02d6d381a268fa42f8a9ebe0c5d2` (Apache-2.0) for cross-node 2-Spark KV sharding and disk-persisted KV checkpoint save/resume, verifying exact output parity against fresh recomputation and measuring KV headroom and save/load I/O vs cold-restart TTFT (`#5`, `#11`).
- `#65` (`spark-copydrafter`): Default-off profile pinning `christopherowen/spark-ds41f@75fb3e72c657534cb6cf0f7a989e0edb4db64a6f` (Apache-2.0) with isolated `CopyDrafter` speculative drafting toggle, verifying lossless token equivalence (greedy and exact stochastic rejection sampling) against non-drafted decoding and measuring single-stream vs multi-stream throughput, acceptance rate, and 131K–1M TTFT (`#6`, `#8`).
- `#66` (`hypertune-kv-adapters`): Default-off comparison pinning `Hyperstitioncc/Hypertune@7aaaf8c2fc88bfb7dfd91019c40428d4528ae121` (MIT) soft-prefill paged KV adapters vs heterogeneous batched LoRA on exact prefix-KV equivalence, decode/prefill throughput, KV-cache overhead, multi-adapter batching scaling, and independently checked co-resident task accuracy (`#25`, `#49`).
- `#67` (`qwen38-longbook-gdn`): Default-off qualification pinning `summerAIO/Qwen3.8-27B-Longbook27-v2@46319430c16af66860b20f14986ad1032e991796` (alias `summerMC/Qwen3.8-27B-Longbook27-v2`, Apache-2.0, all-64-layer GDN conversion) vs base Qwen3.8-27B (48 GDN + 16 full-attention layers) under matched serving/quantization from `8K` to `262K` context on memory footprint, TTFT/throughput, and independently checked long-context recall and frozen agent tasks (`#18`, `#31`, `#32`, `#36`).
- `#68` (`linquant-recurrent`): Related-work record for LinQuant and pure-Rust Gated DeltaNet (GDN) + Mamba-2 recurrent prefill reference verifying exact FP64 algebraic equivalence (`<= 1e-12`) BEFORE measuring naive low-precision vs LinQuant-rewritten state/logit error and prefill throughput, with explicit cross-repository link to `OnixResearch/tt-onix#34` (`#16`, `#32`, `#37`).
- `#69` (`varloop-budget-protocol`): Default-off 4-experiment protocol plus the 2026-11-24 2DSD addendum pinning `thinkingmachines/TML-d24-varloop-research@657b53ba5da7baefe9ff15dca5cd25f5bd3dbaa2`, `SqueezeAILab/2DSD@962874f303c3142406ab3eecfae2bb51567815c9` (`feat/inkling-dspark`, Apache-2.0; noting `main@431aade2` lacks Inkling), and `minseo25/2dsd-inkling-2-mini-varloop-dspark-drafter@57f09bbe7bc67a1643f541a7e568de34f65b5762` (Apache-2.0), verifying greedy 2DSD losslessness before timing, `R = 1, 3, 4, 5` loop-count vs thinking-token budgets using measured 2DSD cost with repetition-filtered and unfiltered columns, first-loop vs final-loop argmax agreement, shared vs separate per-loop KV caches (preserving `#89` boundary), quantization-vs-looping tradeoffs, and the x86_64 + CUDA 13.0 + BF16 GPU host gate (refusing ARM64 Spark or 24 GB substitution).
- `#70` (`ttf-ternary-qwen`): Default-off qualification pinning `oguzeldereli/ttf-home@2f470627050cbb6e163494c2a97eda48c7248d80` (license `NOASSERTION`) 1.6-bpw ternary `{-1, 0, +1}` Qwen3.8-27B vs 4-bit GGUF and FP16/BF16 controls, including a real pure-Rust 5-trits-per-byte ternary quantizer & dequantized matvec parity check against FP64/Q4_0, VRAM/throughput accounting, and independently checked math/code/agent pass rates with explicit code-regression visibility and `cost_per_accepted_task` (`#18`).

## Scope and limitations

All executable harnesses in Batch 7 run deterministically on CPU as `bounded_contract_harness` checks (`synthetic_contract_fixture: true`, `default_enabled: false`). Physical multi-host 10GbE DGX Spark + Apple Silicon Mac Studio setups, 2x/4x DGX Spark RDMA/NVLink/serving clusters, Linux x86_64 CUDA 13.0 BF16 H100/L40S/A100 hosts for 2DSD, 12 GB VRAM modified llama.cpp ternary serving, GPU drafter-adaptation replay clusters, TT-Metal/Blackhole fused GDN prefill hardware (`tt-onix#34`), and unlocated/unverified upstream artifacts (`RLX`, `LinQuant` public code, K2 Horizon `Uno` checkpoints, `LFM3-1.7B`/`d1-2B` checkpoints) are explicitly recorded as `unavailable_hardware_runtime` or `blocked_on_artifacts`. All external X posts, blog posts, model cards, and paper figures remain strictly unverified non-gating references.
